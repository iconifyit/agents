# ADR-001: Global Agents Repository Layout — Visible Source with a `.agents/` Overlay

- **Status:** Accepted (2026-05-28)
- **Version:** 0.0.1
- **Author:** Scott Lewis (with Claude as collaborator)
- **Supersedes:** None (initial ADR for this repository)

## Context

This repository (`iconifyit/agents`) is the single source of truth for all
shared agentic resources — rules, skills, and workflows — consumed across many
project repositories. Each project links the shared resources into its own
`.agents/` directory and layers local additions (`STATE.md`, `config`) on top.

Two forces shape the layout:

1. **Working with the files should be easy.** The agent-tooling convention
   stores resources under a hidden `.agents/` directory. On macOS, a dot-prefixed
   folder is invisible in Finder, which makes the source library awkward to
   browse and edit directly.

2. **`sync-agents` is the engine and it is `.agents/`-bound.** The
   [`@brickhouse-tech/sync-agents`](https://github.com/brickhouse-tech/sync-agents)
   CLI manages the structure. Reading its source confirmed the source directory
   name is hardcoded — `AGENTS_DIR=".agents"` (`sync-agents.sh:14`) — and `index`
   emits `.agents/...` paths into the generated `AGENTS.md`. It cannot be pointed
   at visible top-level `rules/` / `skills/` / `workflows/` folders. Every
   `sync-agents` subcommand operates on a single project root (`--dir`), walking
   up to find a `.agents/` or `.git`.

The question was how to get a Finder-friendly, visible source library without
fighting the tool that has to operate on it.

## Decision

**The repository root holds the real, visible source folders; a hidden
`.agents/` overlay of relative symlinks points back to them.**

```
agents/                       # cloned to a global location (AGENTS_HOME)
├── README.md
├── AGENTS.md                 # generated by `sync-agents index`
├── rules/                    # REAL source — visible in Finder
│   └── *.md
├── skills/                   # REAL source — visible
│   └── <name>/SKILL.md
├── workflows/                # REAL source — visible
│   └── *.md
├── docs/adr/ ...
└── .agents/                  # hidden OVERLAY (relative symlinks)
    ├── rules     -> ../rules
    ├── skills    -> ../skills
    └── workflows -> ../workflows
```

- The visible `rules/`, `skills/`, `workflows/` folders are the canonical files
  you edit.
- The `.agents/` overlay contains only **relative** symlinks (`../rules`, …) so
  the repository is portable to any clone path / machine.
- The overlay makes the repo a valid `sync-agents` workspace, so commands like
  `sync-agents index` and `sync-agents add` work *inside* the global repo
  exactly as they do inside a project. There is no special-casing anywhere.

### Consumer wiring

A consuming project links its `.agents/` subfolders to the **visible** source
folders (single hop), not to the overlay:

```
project/
├── AGENTS.md                 # generated; inherits the global AGENTS.md
├── CLAUDE.md -> AGENTS.md
├── .agents/
│   ├── config                # local — sync targets
│   ├── STATE.md              # local — per-project state
│   ├── rules     -> <AGENTS_HOME>/rules
│   ├── skills    -> <AGENTS_HOME>/skills
│   └── workflows -> <AGENTS_HOME>/workflows
└── .claude/ , .cursor/ , …   # tool dirs produced by `sync-agents sync`
```

Projects depend on the visible source folders, not on the overlay — so the
overlay is purely a global-repo concern and its loss could never break a
consumer.

## Findings that grounded the decision

These were verified with throwaway tests (`/tmp`) before deciding, not assumed:

1. **`sync-agents` is `.agents/`-bound.** Source inspection: `AGENTS_DIR=".agents"`
   is hardcoded; `index` writes `.agents/rules/<name>.md` style paths.

2. **A project can point its `.agents/` subfolders at visible global folders.**
   With a global repo of visible folders (no overlay) and a project whose
   `.agents/{rules,skills,workflows}` symlink to them, `sync-agents index` and
   `sync-agents sync` ran correctly and resolved real content through the chain.
   (`sync-agents index` run *on* the visible-only global repo failed —
   "`.agents/` directory not found" — which is why the overlay is needed for the
   global repo itself.)

3. **The overlay is indexable.** A global repo with visible folders **plus** a
   `.agents/` overlay of relative symlinks (`.agents/rules -> ../rules`)
   produced a correct `AGENTS.md` from `sync-agents index`.

4. **Authoring propagates from any project.** Running
   `sync-agents add skill <name>` / `add rule <name>` inside a *project* created
   the files as **real files in the global repo**, because the project's
   `.agents/` subfolders are symlinks. So new shared resources can be scaffolded
   from any project; you never *must* run authoring commands in the global repo.

## Operational workflow

- **Clone** the global agents repo to a location outside any project repo
  (its path is `AGENTS_HOME`).
- **`agentify`** a project: create its `.agents/`, symlink the three subfolders
  to `AGENTS_HOME`'s visible source, ensure local `STATE.md`, register
  inheritance of the global `AGENTS.md`, regenerate the project `AGENTS.md`, and
  `sync` to the configured tool targets.
- **Edit shared resources** directly in the visible folders, or scaffold new
  ones with `sync-agents add` from any agentified project — either way changes
  land in the global repo and propagate to every linked project instantly via
  the symlinks.
- **Re-run `sync` / `index` only per-project**, and only when *that project's*
  `.agents/` structure changes (new target, new local file). There is no
  cross-repo "propagate" command — propagation is the symlinks, not a command.

## Tooling direction (to be implemented)

`agentify` currently lives in a separate bash tree and hardcodes the global root
to `~/github/@agents`. The agreed direction:

- **Bundle `agentify` into this repo** and `npm init` it, declaring
  `bin: { agentify }` (the existing bash script works as an npm bin) and a
  dependency on `@brickhouse-tech/sync-agents`. Cloning + `npm link` then yields
  both `agentify` and `sync-agents`.
- **De-hardcode the global root** to an `AGENTS_HOME` env/config value so the
  clone location is not baked in.
- Use `npm link` (not `npm install -g`, which copies the package into global
  `node_modules` and would detach the editable source from the clone).

The packaging mechanics are implementation detail and may warrant their own ADR
if they grow.

## Code being removed

None — this ADR is additive. It establishes the initial repository layout and removes no existing code or modules.

## Consequences

**Positive**

- `sync-agents` behaves identically from either end of the pipe; nothing special
  to remember and nothing to special-case in `agentify`.
- The source library is visible and editable in Finder.
- Single source of truth; edits propagate to all linked projects instantly via
  symlinks.
- Consumers link to the visible source, so the overlay is a low-risk,
  global-only concern.

**Negative / risks**

- The `.agents/` overlay is a small redundancy (three symlinks) that must exist
  for the global repo to be a valid `sync-agents` workspace. Relative symlinks
  keep it portable; if it were ever deleted, `git checkout` restores it and only
  global-repo `sync-agents` commands are affected — consumers are not.
- All consumers depend on `AGENTS_HOME` resolving correctly; moving the clone
  requires re-`agentify`ing projects (re-pointing their symlinks).

## Alternatives considered

- **A1 — visible folders only, no overlay.** Simplest tree, but the global repo
  could not generate its own `AGENTS.md` via `sync-agents index`, and authoring
  helpers (`add` / `import`) could not run in the global repo. Rejected: it
  fights the tool and would require hand-rolling the global index.
- **A3 — `.agents/` as the real source, visible symlink aliases at root.**
  Zero friction for `sync-agents`, but it inverts the intuitive source-of-truth
  (the "real" files stay hidden; the visible folders are the aliases). Rejected
  in favor of visible-is-real, which matches how the library is actually edited.
