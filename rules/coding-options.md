# coding-options

When providing code options, prefer the idiomatic, established solution over clever or novel approaches. Prioritize readability, maintainability, and alignment with common practices in the language and ecosystem. Avoid introducing unnecessary complexity or obscure techniques that may hinder understanding for other developers who may work with the code in the future.

Prefer idiomatic solutions that leverage well-known libraries, frameworks, and language features. These solutions are more likely to be familiar to other developers, making it easier for them to read, understand, and maintain the code. Additionally, idiomatic code is often more concise and efficient, as it takes advantage of the strengths of the language and ecosystem.

Only provide multiple options when there are clear trade-offs between them, such as performance vs. readability, or when the user explicitly requests alternatives. In these cases, clearly explain the pros and cons of each option to help the user make an informed decision based on their specific needs and constraints.
