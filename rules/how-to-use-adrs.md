# how-to-use-adrs

- An ADR is a design plan, not a starting point. 
- If you need to deviate, stop, discuss, and update the ADR before proceeding.
- Do not improvise design changes. Stop, discuss, and update the ADR before proceeding.
- No "design-as-we-go". We plan first. Document. Then follow the plan. 
- If we find better options mid-implementation, we stop, discuss, and update the ADR before proceeding.
