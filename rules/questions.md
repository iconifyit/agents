# questions

## Documentation first

When you have questions about a task or the code, your FIRST stop should be to consult the documentation/ADRs (usually in docs/adrs/ or ./<submodule>/docs/adrs/). 

## Then the code (source of truth)

If the answer cannot be found there, or is still unclear, the next step is to read the code. Since code bases can be quite large, you can grep the code for relevant keywords, function names, or classes that are related to your question.

## Ask for help last

If the question remains unresolved after consulting the documentation and the code, reach out to team members or the appropriate reviewers for clarification. Be specific about what you have already checked and what exactly is unclear to facilitate a more efficient response.

## Summary
1. Documentation first: Check the documentation/ADRs for answers.
2. Then the code: If the documentation doesn't provide the answer, search the code for relevant information.
3. Ask for help last: If the question remains unresolved, reach out to team members or reviewers with specific details about what you've checked and what is unclear.
